# Project guidance

Preserve the approved architecture in docs/ARCHITECTURE.md and the Italian dashboard guidance in apps/dashboard/AGENTS.md. Runtime processes keep separate database roles and credentials. Trading, external AI and MT5 remain disabled until their respective implementation and acceptance gates pass. Telegram enrollment is an explicit local operator action; source configuration belongs in the authenticated dashboard.

## Living Italian documentation

The user requires two maintained documents: docs/cliente/GUIDA_CLIENTE.md and docs/team/GUIDA_PREPARAZIONE.md, with the matching Word deliverables in those directories. Update documentation only when necessary: when a change makes documented behavior, instructions, environment variables, account requirements or safety controls inaccurate or incomplete, or when the user explicitly requests a documentation change. Do not update guides, revision dates or Word files for internal refactors, tests or changes with no documented impact. Update only affected guides and sections; update both guides when both audiences are affected. Keep the Italian text concise and use diagrams where they clarify the flow. Keep docs/cliente/FLUSSO_SISTEMA.html and shared illustrations aligned when the represented flow or availability changes. For each changed guide, date the revision in Europe/Rome, append a concise revision entry, distinguish implemented and verified features from configurations still required and future capabilities, and regenerate its matching Word file. Use the Documents skill and visually verify every rendered page before delivering an updated Word file. Never include actual credentials, session material or personal source messages in examples or artifacts. Keep necessary updates part of the feature work; no recurring automation is implied.
